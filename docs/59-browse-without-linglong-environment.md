# 缺少玲珑环境时的浏览体验

## 背景和目标

玲珑商店的推荐、分类、搜索和详情来自远端 API，不应因为本机没有 `ll-cli` 而被启动流程阻断。环境缺失、仓库读取失败或系统包管理器不可用时，用户仍能进入商店；依赖本机能力的动作继续要求真实环境通过检测。

本次复用 `LinglongEnv`、环境安装/修复弹窗和现有队列，不增加独立平台通道，也不在每张卡片上发起检测。相比页面各自保存“体验模式”标志，统一能力快照能让安装后的恢复、设置诊断和后台任务保持一致。

## 行为契约

- 每次进程启动检测环境一次。成功按原流程初始化；失败完成浏览启动，进入推荐页后提醒一次。
- 提醒提供继续浏览、手动安装、自动安装、重新检测和现有修复入口。继续浏览仅关闭提醒，不将环境标记为可用。
- 推荐、分类、搜索、详情、截图和分享不依赖玲珑环境，可正常体验。
- 我的应用、玲珑进程和更新页面在缺环境时显示说明及配置入口。不能把未知本机列表显示成“没有应用”或“全部最新”。
- 安装、更新、指定版本安装、打开、卸载、快捷方式和本机维护动作通过统一提示入口检查能力；未满足环境时不创建任务或触发 CLI。
- 安装队列底层也拒绝缺环境时的单个/批量入队、人工重试和自动出队。已有任务、历史与恢复记录保留，缺环境不能使用空安装列表核验任务成功。
- 环境管理的诊断、安装和修复入口仍可使用；服务故障时不能把恢复手段本身禁用。
- 修复通过后补做已安装列表、更新及队列恢复；之后才消费等待协议请求和恢复持久化副作用。恢复不重发启动访问记录、不重复导航首页。
- 自动安装运行时保持原有真实安装事务，不提供只修改界面状态的假取消。

## 状态与性能

`LinglongEnvState.isReady` 仅由真实 `result.isOk` 决定。`isUnavailable` 表示已有明确失败结果，区别于尚未检测；重新检测保留上一次能力事实。检测中的并发调用共用一个 Future，提示框在同一根 Navigator 下合并。

页面只订阅能力布尔值，操作在点击时读取状态；不让安装进度高频变化重建全部卡片。缺环境时不预热 CLI 搜索索引、不轮询玲珑进程、不启动已安装差量检测，也不反复执行失败的恢复动作。隐藏页保持原有 KeepAlive 和可见性控制。

环境恢复沿用 Provider 和应用层初始化，限制并发及旧请求回写，不新增持续轮询环境的计时器。

## 验证范围

回归测试覆盖无 CLI/服务不可用时浏览完成、继续浏览不授予安装能力、重复检测合并、页面说明、操作被拦截、队列保留及恢复初始化。完整 Flutter 测试、静态分析、国际化资源和 RTL 门禁以及 Linux Release 构建用于验收。

云容器已从经过签名与摘要验证的源安装真实 `ll-cli 1.12.3`；CLI 版本命令成功。容器没有系统 D-Bus 和 systemd，`ll-cli --json list` 与 `repo show` 返回包管理器无法连接，不能声称真实安装、卸载或服务修复已验收。测试使用依赖替身覆盖恢复状态，桌面验证覆盖缺环境/服务不可用的真实渲染。

本次自动化验收：全量 Flutter 测试 1366 项通过、12 项原有跳过；静态分析零问题；Linux Release 构建、helper/Impeller 产物检查通过；原生 helper 75 项、强调色 42 项检查通过。全部 10 种语言资源与 RTL 门禁通过。首次代码生成检查会识别本功能新增的已修改生成文件，需要将它们与源文件一同提交后复核一致性。

桌面实测点击「继续浏览」后推荐 API、Banner 和应用卡片正常显示；进入更新页显示环境配置说明。环境尚未就绪时点击卡片安装，展示统一提示而不启动安装任务。真实包操作、完整管理员授权与实际桌面环境下的性能指标仍需具备系统玲珑服务的主机验收。
